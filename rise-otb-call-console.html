01 · Frame

Call at a glance

Keep the call anchored on one outcome: a file they recognize, processed in front of them, with a measured agreement rate.

Goal

Process their new file end-to-end

Upload, register, configure, run, and read the result together. Do not hand-wave the middle.

Client brings

Validation CSV

Walmart URL + comparison URL. If they have expected Match_Type / Notes, we use them as the calibration target.

We show

The real dashboard path

Storage upload → dataset scan → recipe wizard → run → merged CSV. No hardcoded pilot walkthrough.

Success looks like

Baseline + residual list

An agreement number against their labels, a tuned profile, and every remaining difference classified with an owner.

Set the expectation early: this is a calibration run, not a promise of 100% agreement. Two-sided attribute conflicts and delisted pages are hard limits in the current compare plugin; we will name them.

Opening script

“Thanks for sending the file. Today I’ll show you exactly how it moves through the pipeline, and then we’ll compare our verdicts to your expected labels so we can calibrate the matching profile.”

Closing script

“We’ll save this profile, re-run your file, and send a recap with the agreement rate and the residual differences. If a difference is a policy call rather than a config call, we’ll list it separately.”

04 · Route the file

Intake decision tree

The CSV columns decide the pipeline. Do not force a compare run on a coverage or dedupe file.

Compare

Walmart URL + comparison URL

Has Walmart_Url and Comp_Url (Amazon).

Run Walmart Scrape & Compare v2. Live run is safe; validation does not use ScraperAPI.

Coverage

Walmart URL only

Has Walmart_Url but no comparison URL.

Run Walmart Coverage v1. It searches for the Amazon equivalent.

Dedupe

Feed columns

product_id, pt, brand, upc, title and similar.

Do not run live. ScraperAPI quota is exhausted. Capture as a follow-up.

If the columns are mixed or unclear: stop and map them before uploading. A wrong column choice looks like a product-quality problem, not a configuration problem.

05 · Before upload

CSV preflight

Thirty seconds of hygiene saves a three-minute re-run.

Required shape

  • Four core columns: prmry_sku_id, Walmart_Url, comp_item_id__1, Comp_Url.
  • Expected columns, if present: Match_Type, Notes, optionally Match_Type_Comments.
  • UTF-8, ideally without a BOM.
  • No blank rows; no duplicate prmry_sku_id values.
prmry_sku_id,Walmart_Url,comp_item_id__1,Comp_Url,Match_Type,Notes
194305312,https://www.walmart.com/ip/194305312,B0012OG95S,https://www.amazon.com/dp/B0012OG95S,Incorrect Match,Color

Red flags

  • Triple-quote artifacts: """194305312""" → normalize to 194305312.
  • URLs without http, or Walmart URLs without /ip/.
  • Amazon URLs without /dp/ or /gp/product/.
  • Expected labels other than Exact Match / Incorrect Match.
  • Notes containing multiple attributes; the plugin returns one primary note.

If the file is over 100 rows, run a 10-row sample first and queue the full file after the call.

Calibration console

}

Advanced keys

KeyUse it for
note_priorityWhich attribute becomes the single primary note when several differ. Default: Color → Size → Ounce → Volume.
note_labelsRename a token to the client’s wording, e.g. {"Ounce": "Weight"} or {"Color": "Colour"}.
not_found_noteCustomize the 404 text. It cannot be blanked through config.
weightsConfidence only: UPC 0.50, brand 0.20, title 0.15, size 0.10, color 0.05. Partial overrides are normalized. It does not suppress a two-sided conflict.

Diff protocol

  1. Join on prmry_sku_id; strip quote artifacts.
  2. Normalize labels to Exact / Incorrect.
  3. Compare Match_Type first, Notes second.
  4. Bucket: FALSE_EXACT, FALSE_INCORRECT, NOTE_ONLY, DELISTED, MISSING_DATA.
  5. FALSE_EXACT → Strict. FALSE_INCORRECT → Lenient only if no two-sided conflict.
  6. Record label agreement and label + notes agreement separately.

Hard limits — config cannot fix these

SymptomWhyWhat to do
We say Incorrect; they say Exact; note is Color / Size / Ounce. A two-sided attribute conflict hard-blocks Exact. A weight of 0 does not ignore it. Explain the difference. Offer a code-level ignore/canonicalization change if it is a policy call.
We say Incorrect; they say Exact; note is 404. Delisted page. The plugin flags the scrape failure. Show the HTTP 404. Do not fake a match.
Their note is Brand / Title / other. Notes are limited to Color, Size, Ounce, Volume. Map to the closest token or scope a code change.
Their Match_Type_Comments wording differs. The output wording is fixed. Confirm whether the wording is contractual; if so, scope a change.
We say Exact; they say Incorrect; note is blank. Title-only matching or UPC bypass over-called it. Switch to Strict; disable title-only and UPC bypass.
One side is missing attributes. One-sided gaps do not block Exact; they can still distort confidence. Re-run the row or route it to review; do not hand-edit the verdict.

09 · Language

Say / avoid

Precise language protects trust and avoids promising product behavior that is not shipped.

Say

  • “Today we’ll process your file and calibrate to your labels.”
  • “Two rows are delisted; we flag 404 rather than fake a match.”
  • “This is a calibration run; we’ll lock the profile after we see your expected output.”
  • “The comparison runs at about 25 seconds per row on one agent.”
  • “We keep the residual differences visible.”

Avoid

  • “100% match” before calibration.
  • “Real-time” or “instant.”
  • “The review queue is ready.”
  • Any pricing number, discount, or currency comparison.
  • “Unlimited rows” or “no rate limits.”
  • Blaming Amazon/Walmart for every diff without showing the evidence.
