Architecture How It Fits Together

Three tiers: a Go agent on each device, Supabase (PostgreSQL + Deno Edge Functions) for orchestration, and S3 for all data storage.

🤖

Go Agent

Single binary running on each device. Picks up jobs via Realtime WebSocket, executes plugins in sandboxed subprocesses, manages merge operations with distributed locking.

22 packages60+ files
🗄️

Supabase PostgreSQL

State store for orgs, members, datasets, chunks, jobs, executions, devices, plugins, signing keys. Triggers auto-create scan jobs on dataset insert and call pre-chunking on scan completion.

18 tablestriggers
🦕

Edge Functions

13 Deno TypeScript functions handling pipeline activation, chunk planning, job completion chaining, merge scheduling, device registration, and storage config.

13 functionsDeno runtime
📦

S3 Storage

Supabase S3 bucket holding source CSVs, pipeline chunks (.bin/.out), and final merged datasets. Access via S3 v4 signing with per-org credentials from vault.

custom v4 signerpre-warmed TLS
🔗

Auto-Advancing Pipeline

complete_job → advance_pipeline → plan_dataset_chunks → new jobs. Every job completion triggers the next step automatically. No cron, no polling, no manual advancement.

chain reactionautonomous
🧪

Plugin Sandbox

Per-platform isolation: macOS Seatbelt, Linux cgroups/namespaces/seccomp, Windows job objects. Network blocked by default, resource limits enforced, Ed25519 signature verification.

zero-trustsandboxed

Key insight: Each pipeline step is a plugin — a standalone binary the agent downloads, cryptographically verifies, runs in a sandbox, and discards. The pipeline template defines which plugins run in which order. The system handles all scheduling, execution, and cleanup.
